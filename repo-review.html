What to preserve

The core idea is worth protecting.

The right response is not to simplify this into a conventional article. The generative scenes are the argument. The work should become more legible and reliable without becoming ordinary.

01

Interaction and thesis reinforce each other

The sand, flocking, wave, network, and morphing-city scenes are not decorative illustrations. They make emergence and form tangible. That is the project’s strongest product decision.

02

The visual language is unusually coherent

Sand, violet, sea green, near-black, and particle motion create continuity across chapters with different mechanics. The page feels authored even where its editorial scaffolding feels familiar.

03

Canvas lifecycle work shows care

The shared 2D helper handles DPR, resize, pointer state, intersection gating, and cleanup. The Three.js scenes also dispose geometries and renderers. This is better than most experimental front ends.

Priority findings

Fix the release blockers before refining the aesthetic.

Five issues account for most of the risk. The first four are major because they affect comprehension, access, performance, or trust.

P1 · Major
Opening experience

The hero intro is partly invisible.

The GSAP context is scoped to the WebGL mount, but .hero-line and .hero-fade live outside that element. GSAP cannot find them. Because the supporting elements also carry opacity-0, the kicker, explanation, and scroll cue remain hidden.

  • Move the section content inside the scoped wrapper, or scope GSAP to a section ref.
  • Make the default DOM state readable; animation should enhance visible content, never unlock it.
  • Add a browser test asserting that the hero lede becomes visible after first paint.
Evidence Repeated runtime warning GSAP target .hero-fade not found src/sections/Hero.tsx:206–225
P1 · Major
Accessibility and control

The essay has no non-motion, non-canvas route through its ideas.

All 11 canvases have no accessible name or fallback text. The imported stylesheet contains no active reduced-motion override. Desktop chapter navigation disappears below 768px, leaving mobile readers in an 11,636px document without a chapter index. Several 40%-opacity body styles land below WCAG AA contrast.

  • Add reduced-motion and reduced-data quality modes that render static chapter posters.
  • Give each canvas a meaningful adjacent description; mark purely decorative canvases hidden.
  • Provide a compact mobile chapter menu and persistent “skip animation” control.
  • Raise supporting copy to a tested AA color and add explicit keyboard focus styles.

P1 · Major
Performance architecture

Every chapter pays its runtime cost up front.

The single production chunk is 916.7 KB before gzip. Three.js, GSAP, ScrollTrigger, every chapter, and all generated geometry enter the initial route. Intersection observers pause most off-screen loops, but construction, parsing, allocation, and the hero’s permanent animation still happen.

  • Lazy-import chapters near the viewport and split Three.js scenes into separate chunks.
  • Start with static poster frames; hydrate interaction after intent, visibility, and device checks.
  • Pause the hero loop after it leaves the viewport and on visibilitychange.
  • Define budgets: initial JS < 250 KB gzip, no long task > 50 ms, stable 45+ FPS on a mid-range phone.

P1 · Major
Editorial trust

Factual and medical claims are presented as atmosphere.

The essay invokes cancer detection from breath, the antiquity of smell, silicon manufacture, and a line attributed “after Demis Hassabis,” but contains no notes, links, or source list. The stronger the visual confidence, the more conspicuous that absence becomes.

  • Move chapter copy into structured content with a sources field.
  • Add unobtrusive footnote markers and a final references section.
  • Use exact quotation marks only for verified wording; otherwise paraphrase without quote styling.
  • Have a domain reviewer check the cancer-detection phrasing before publication.

P2 · Minor
Repository shape

The scaffold is larger than the product.

Fifty-three generic UI component files make up most of the source tree even though the essay does not import them. Their dependencies create installation and lint surface area, and the generated components account for all ten current lint errors. The README and package name remain template defaults.

  • Delete unused UI components and remove their unused dependencies.
  • Replace the template README with architecture, content, performance, and verification notes.
  • Rename my-app, remove stale App.css, and drop the inspection plugin from production config.
  • Add smoke, accessibility, and visual regression tests for the representative chapter pattern.

P2 · Minor
Art direction

The imagery is distinctive; the editorial frame is not.

Fraunces + Space Grotesk + IBM Plex Mono, repeated numbered kickers, ruled separators, and a uniform six-tile grid match a saturated AI-era editorial pattern. The deterministic scan flags the first two fonts. This does not erase the project’s originality, but it makes the authored simulations feel more templated than they are.

  • Keep the palette and simulations; vary chapter composition according to each idea.
  • Use chapter numbers only in actual navigation, not as repeated heading decoration.
  • Replace one or more reflex fonts with a more specific typographic voice.
  • Let the “Forms” chapter behave as an instrument rack, not six identical cards.

Recommended sequence

One hardened chapter pattern, then spread it.

Do not rewrite the whole essay at once. Prove the new chapter contract on the opening and “Touch,” then apply it to the remaining simulations.

Repair the opening

Fix GSAP scope, visible defaults, console warnings, anchor behavior, and mobile navigation.

Done whenThe complete hero message is visible with JavaScript delayed, animation off, and at 200% zoom.

Define the accessible chapter contract

Every chapter gets a heading, explanation, interaction instructions, canvas description, poster, and reduced-motion behavior.

Done whenKeyboard and screen-reader users receive the same argument, even if not the same sensory effect.

Progressively load the runtime

Lazy-import chapter engines, limit active canvases, pause hidden tabs, and add quality tiers.

Done whenInitial JS meets budget and a mid-range phone holds a stable frame rate through the representative flow.

Add editorial provenance

Extract chapter data, verify quotations, attach primary sources, and publish a references section.

Done whenEvery factual or medical claim can be traced without interrupting the visual rhythm.

Remove scaffold and pin behavior

Delete unused components and dependencies; add smoke, a11y, visual, and performance checks; rewrite project docs.

Done whenBuild, lint, tests, and budgets pass from a clean install using one documented command.

Re-art-direct the repeated frame

Keep the simulations and palette, but give each chapter a composition shaped by its subject rather than the same numbered header.

Done whenThe chapter type can be guessed from its spatial behavior, not from its label.
